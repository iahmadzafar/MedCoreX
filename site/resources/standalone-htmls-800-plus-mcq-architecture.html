01 Recognition — Name It
Pattern recognition from a clinical vignette. Most are diagnosis tasks.
›
Diagnosis — stated
What

The stem hands you a complete clinical picture and asks for the disease name outright.

Stem
[Age/sex] + [presenting complaint] + [2–4 discriminating findings] + "most likely diagnosis?"
Where

The discriminator is almost always a modifier inside the stem — the word that flips the answer: sudden vs gradual, painless vs tender, site (DIP vs MCP), timing (weeks after sore throat vs during URTI).

Trap

Options are sibling diseases in the same system. You lose by picking the sibling that matches half the stem. Name all four options first, then find the one line that separates them.

Steps
  1. Read only the last sentence — confirm the task is "name the disease".
  2. Write the 3 findings that matter most; ignore age and background noise.
  3. For each option, ask: does it explain all three? One will. That is the answer.

Diagnosis — implied
What

No question sentence at all. The stem is a bare vignette and the options are four disease names. The task is still diagnosis.

Stem
[Age/sex] + [finding] + [finding] + [finding] — then straight into options.
Where

No explicit ask means the option set defines the task. Read the options before the stem if the stem has no question mark — that is the whole trick to this type.

Trap

These feel ambiguous and slow you down. They are not harder than stated diagnosis; they are just missing the instruction line.

Steps
  1. If there is no question sentence, read the four options first — they tell you what is being asked.
  2. Identify what the vignette is pointing at (organ system, then process).
  3. Apply the same discriminator test as any diagnosis question.

Steps

  2. Attach the fact to a hook (a rule, a mnemonic, a comparison) so it survives.
  3. If you did not know it, mark it in the error log — this is the cheapest kind of mark to recover.

Recall — worded as a fact question
What

Same retrieval demand, phrased as "cause of", "which of the following is true", "most widely used".

Stem
"Cause of X?" / "All of the following are true about X except" / "Drug of choice for X?"
Where

The discriminator is the specificity of the fact. Broad true statements lose to narrow precise ones.

Trap

When several options are technically true, the setter wants the most specific / most characteristic one. Rank them, do not scan them.

Steps
  1. Accept that multiple options may feel true.
  2. Pick the one that is most characteristically true — the one you would quote in clinic.
  3. Convert to a flashcard immediately; this type is pure accumulation.

04. Option Patterns

Sharp, minimal.
›
Seven patterns
  • Sibling → find pivot
  • Category → check task
  • Modality → initial vs confirmatory
  • Lookalike → own difference
  • Severity → match word
  • Supportive/Definitive → unstable→resuscitate
  • True-but-irrelevant → answer asked task

05. Solve

Six steps.
›
1. Task

Read the last line first and name the task in three words — diagnosis, test, management, next step, mechanism, recall. The task decides which memory you search. If there is no task line, read the options first.

›
2. Pivots

Find the two or three findings that separate the options, not the whole story. Ignore age, sex and background unless one of them is the discriminator.

›
3. Predict

Say the answer in words before you read the options. Four seconds. It stops you accepting the first plausible option.

›
4. Match

Look for your prediction in the option set. If it is absent you have misread the task or do not know the fact — go back to step one before eliminating.

›
5. Eliminate

Remove options answering a different task, then wrong-category options, then the sibling that fails one pivot. Three usually fall at once.

›
6. Commit

No negative marking. Never leave a blank. If two survive, take the more specific and move on.
